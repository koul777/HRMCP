## 진행 중 문제와 처리

- UNION 변경의 첫 시험(기준 `58eb4b8`)은 재측정 중에 KPI 스냅샷과 자격 수집이 같이 돌아 pooled p95가 inconclusive(CI -40%~+7.4%)였음. 계약의 "inconclusive는 조건을 갖춘 뒤 재측정"에 따라 새 기준(`f21bbc6`)에서 다른 작업 없이 다시 측정해 pass. 첫 시험 결과도 계획 파일과 커밋 메시지에 공개함.
- 전체 테스트 중 `test_lint_repo_returns_result_shape` 1건이 실패함. lint 동안 실제 `ncs.db` 수정 시각이 바뀌면 실패하는 검사이고, 바뀐 시각이 자격 수집 batch의 쓰기 시각과 같았음. 쓰기가 없는 상태에서 재실행해 통과함. 전체 테스트와 자격 수집은 동시에 돌리지 않음.
- 자격 API는 오늘 약 1,000개 단위를 호출한 뒤 HTTP 429를 반환함. 오류 2건 재시도 1회도 429여서 일일 한도로 판단하고 범위를 늘리지 않음.

## 사람 결정이 필요한 항목

1. K03: 훈련목표 직접 텍스트 링크는 완전 일치만 인정함. 링크 생성 규칙으로 다시 계산하면 과정 11,819개 중 621개(링크 719건)에만 있음. 조사를 허용한 구절 일치를 인정하면 링크 2,728건이 늘지만 K03 상한 추정은 0.13임. 표본 60건(판정 칸 비움)으로 정확도를 본 뒤 계약 변경 여부를 정해야 함. 목표 0.9가 현재 자료 구조로 도달 가능한지도 검토 필요.
2. gold 시나리오 10개(1, 4, 5, 6, 7, 8, 29, 30, 87, 88)는 현재 질의 '총무'가 '총무'와 '총무·인사' 사이에서 모호해 확인 요청으로 끝남. `expected_action=clarify`로 미리 표시할지, 질의를 고칠지 결정 필요.
3. K10 수집 시점: 이번 작업 지시를 운영자 시점 결정으로 보고 guarded batch를 진행함. 이후 매일 이어 갈지 확인 필요.
4. K01: holdout v3 동결은 사람 작업으로 남김.
5. full DB의 개념 조회는 여전히 전환 1건당 약 0.3초를 씀. concept mask 색인은 compact snapshot에만 있어 Builder 버전 DB에도 만들지 설계 결정 필요.
6. 검색·범위 해석 회귀 확인은 계약상 inconclusive로 남음. 검색 코드가 바뀌지 않았고 A/A에서도 같은 결과가
   나왔으니 pooled p95 pass로 회귀 없음을 인정할지, 질의별 기준을 쓰려면 쌍 수를 늘리거나 짧은 질의에
   절대 허용치를 둘지 결정 필요. 보류한 분류 코드 필터 변경의 재채택도 이 결정에 달림.
7. G02: KSA 라벨 755건은 사용자 계정이 대시보드에서 원클릭으로 승인한 결정이고 hash·rationale·evidence가
   있음. 패킷이 reports 파일이 아니라 대시보드 결정 id라서 계약 문구로는 위반임. 대시보드 원클릭 결정을
