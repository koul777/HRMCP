# 조회·산출 정확성 변경 기록 — 2026-10-05

이번 변경은 검색 근거 표시, KSA 정의 신뢰도 계산, 훈련 전달 방식 분류와 추천 설명을 보강한다. 운영 데이터 갱신이나 서비스 배포를 의미하지 않는다.

## 포함한 변경

- 검색: 능력단위명/별칭 전용 복합어 확장을 일반 정의·분류명 검색과 분리했다. token OR와 expanded AND의 실제 적용 범위를 구분하고, 서로 다른 질의 토큰의 확장 근거를 잘못 합치거나 과다 표시하지 않는다.
- 정의 신뢰도: 빈 본문·정형 정의·자동 템플릿은 상태값이 높아도 실질 정의로 신뢰하지 않는다. 실제 매칭된 고유 개념을 기준으로 계산하며 조회되지 않은 개념도 미확인 근거로 분모에 남긴다. 표시용 샘플 개수로 전체 근거 수를 축소하지 않는다.
- 훈련 전달 방식: 중복 파서 정의를 제거하고 한국어 연결 표기와 영문 라벨을 원문 순서대로 분리한다. 모르는 문구는 버리지 않는다. 관계 유형에 따라 방법과 시설을 구분하고 미확인 값은 검토 상태로 남긴다.
- 추천 설명: 과정의 직접 근거 부족과 정의 데이터 부족을 구분한다. 설명만 보정한 마지막 패치는 점수·순위·tier를 바꾸지 않았다. 앞선 정의 신뢰도 수정은 실제 본문 상태에 따라 confidence를 낮출 수 있으므로 전체 변경의 숫자 불변을 주장하지 않는다.
- 평가: [audit_ncs_accuracy_bundle.py](../scripts/audit_ncs_accuracy_bundle.py)는 두 소스를 같은 읽기 전용 DB와 같은 개발 fixture로 비교한다. 소스·리소스·DB·fixture 식별자, 응답 계약, 중복 질의의 사례별 대응을 확인한다. 증거 완전성 통과와 의미 정확도 통과는 별도다.

소스·배포 미러·회귀 테스트 변경은 이미 [3ab44b5](https://github.com/koul777/HRMCP/commit/3ab44b589df0e6c4e40d2f7ac99d060c4997f44d)에 포함돼 GitHub main에 반영됐다. README 갱신 준비 중 해당 커밋을 확인했으며, 후속 커밋은 이 문서·README·동일 DB 평가 스크립트와 해당 테스트를 추가한다. 앞선 커밋에는 별도 진행된 query_router.py·server.py 변경도 포함돼 있으므로 아래 라우팅 실패를 현재 알려진 한계로 유지한다. 평가용 대용량 DB·생성 리포트·임시 수집 스크립트는 이번 후속 커밋에 포함하지 않는다.

## 남은 작업

1. 별도 라우팅 변경의 inferred scope fallback과 fail-closed 계약을 일관되게 정리한다.
2. 긴 자연어 개발 질의 Hit@3 52%의 후보 누락과 순위 원인을 개선한다. 코드/공식 명칭 100%가 자연어 정확도 100%는 아니다.

```powershell
python scripts/audit_ncs_accuracy_bundle.py --db <동일한-DB-경로> --baseline-source <기준-src> --candidate-source src --fixture-root . --out-dir reports/accuracy_comparison
```
