# 7단계 — 독립 holdout 구축과 일반화 기준선

작성일: 2026-09-11

## 배경

5단계에서 40개 질의 기준 Hit@3를 0.500에서 0.875로 올렸다. 그러나 그 40개는 intent alias를
**설계할 때 사용한 세트**이므로 in-sample 수치이고, 일반화 여부를 알 수 없었다. 5단계 보고서도
"완전히 독립적인 holdout이라고 볼 수 없다"고 기록했다.

이 단계에서 기존 40개를 회귀 세트로 고정하고 독립 holdout을 구축해 정직한 기준선을 측정했다.

## holdout 구축 방법

alias 목록을 보고 질의를 쓰면 holdout도 오염된다. 이를 피하기 위해 다음 절차를 따랐다.

1. 기존 40개가 사용한 42개 능력단위 코드를 제외한 후보 풀을 DB에서 추출했다.
2. 각 후보의 `api_definition`(NCS 공식 정의문)을 읽고, 그 정의가 서술하는 업무를 실무자가
   어떻게 부를지로 질의를 작성했다. 공식 능력단위명을 그대로 쓰지 않았다.
3. 학습 세트에 있는 능력단위에 대해서도 **새로운 표현**을 별도로 작성해 alias의 표현 일반화를
   함께 측정했다.
4. 카테고리는 기존 `NL_CATEGORIES` 5종을 유지했다. 사무행정 능력단위는 총무로 분류했고,
   경영기획 8건은 HR 실무로 정직하게 라벨링할 카테고리가 없어 제외했다.

### 구성

| 항목 | 값 |
|---|---:|
| 질의 수 | 51 |
| 무효 능력단위 코드 | 0 |
| 기존 40개와 질의 중복 | 0 |
| holdout 내부 중복 | 0 |
| 기대 능력단위(고유) | 54 |
| 학습 세트에 없던 능력단위 | 24 |
| 학습 세트와 겹치는 능력단위(재표현) | 30 |

카테고리 분포는 인사 13, 노무 8, 교육 7, 총무 14, 회계 9다.

파일: `tests/fixtures/ncs_search_eval_nl_holdout.json`

## 결과

| 세트 | 질의 | Hit@1 | Hit@3 | MRR@10 | 검색 오류 |
|---|---:|---:|---:|---:|---:|
| 학습 40개 (회귀 세트) | 40 | 0.8500 | 0.8750 | 0.8675 | 0 |
| **독립 holdout** | 51 | **0.3922** | **0.4510** | **0.4408** | 0 |
| 격차 | | -0.4578 | -0.4240 | -0.4267 | |

5단계의 0.875는 in-sample 수치였고, 일반화 성능은 0.451이다.

### 카테고리별 holdout 성능

| 카테고리 | 질의 | Hit@1 | Hit@3 | MRR@10 |
|---|---:|---:|---:|---:|
| 회계 | 9 | 0.7778 | 0.7778 | 0.8125 |
| 교육 | 7 | 0.5714 | 0.5714 | 0.5918 |
| 인사 | 13 | 0.3077 | 0.3846 | 0.3631 |
| 노무 | 8 | 0.3750 | 0.3750 | 0.4146 |
| 총무 | 14 | 0.1429 | 0.2857 | 0.2134 |

### 핵심 관찰: 학습된 능력단위에서 오히려 더 나쁘다

| 기대 능력단위의 출처 | Hit@3 |
|---|---:|
| 학습 세트에 있던 단위를 **새 표현**으로 질의 | 9/29 = **0.310** |
| 학습 세트에 **없던** 단위를 질의 | 14/22 = **0.636** |

직관과 반대되는 결과다. alias가 특정 표현에 고정돼 있어 표현이 바뀌면 발동하지 않고, 그러면
그 아래의 기본 랭킹이 그대로 드러난다. 반면 학습되지 않은 단위는 질의에 공식 명칭 토큰이
그대로 포함되는 경우가 많아 기본 phrase/token 매칭이 작동한다.

즉 **alias 층은 표현에 취약하고, 그 아래 기본 랭킹이 약하다.**

## 실패 유형 분석

28건의 실패는 세 갈래로 나뉜다.

### 1. 범용 행정 토큰이 전 분야를 끌어온다 (가장 심각)

`처리`, `관리`, `계획`, `수립`, `기준`, `체계`, `준비`, `대응` 같은 토큰 하나가 24개 대분류
전체에서 매칭돼 정답을 밀어낸다.

| 질의 | 상위 3건 |
|---|---|
| 퇴직 정산 서류 **처리** | 심냉처리, 퀜칭열처리, 진공열처리 |
| 그룹웨어로 결재 **처리** | 심냉처리, 퀜칭열처리, 진공열처리 |
| 적격증빙 수취와 전표 **처리** | 심냉처리, 퀜칭열처리, 진공열처리 |
| 인원 충원 **계획 수립** | 작업계획수립 ×3 |
| 출퇴근 **기록 관리** | 경기기록분석 자료관리, 환경 기록 관리 |
| 직급 승격 **기준** 마련 | 평가기준 개선, 지적기준점측량, 평면기준점측량 |
| 평가 등급 **체계** 설계 | 지능형교통체계 효과평가, 스마트물류체계 성과평가계획 수립 |

금속 열처리 능력단위가 HR·회계 질의 1위를 차지하는 것은 단순 품질 문제를 넘어, 직무기술서
근거로 쓰일 때 명백히 잘못된 산출물을 만든다.

### 2. 개념은 맞지만 분야가 틀리다

| 질의 | 기대 | 실제 상위 |
|---|---|---|
| 퇴직 예정자 전직 지원 프로그램 | 전직지원(인사) | 전직지원 연구, 전직지원상담 감독 (직업상담) |
| 교육 효과 측정 | 교육성과 평가 | IT기술교육 성과평가 |
| 워크숍 행사 준비 | 행사지원관리(총무) | 웨딩 행사 준비, 연회 행사 준비 |
| 업무용 차량 배차 관리 | 차량운영관리(총무) | 철도차량 생산관리, 특수차량 안전관리 |
| 출입 통제와 보안 점검 | 총무보안관리 | 항공기 보안, 공항보안검색 |

HR 문맥 신호가 랭킹에 전달되지 않아, 같은 개념의 타 분야 단위가 이긴다.

### 3. 상위어·하위어 혼동

`엑셀 스프레드시트 문서 작성`이 `사무자동화 프로그램 활용` 대신 `문서 작성`을 반환하는 식이다.
질의의 구체적 수단(엑셀)보다 일반 동사구가 우선된다.

## 권고

1. **전역 동의어를 늘리는 방향은 답이 아니다.** 이번 결과가 그 접근의 한계를 수치로 보여준다.
   표현마다 alias를 추가하면 학습 세트만 다시 오르고 holdout은 그대로다.
2. **범용 행정 토큰의 가중치를 실질적으로 낮춰야 한다.** 1번 유형이 28건 중 다수를 차지하며,
   가장 적은 변경으로 가장 큰 효과를 낼 지점이다. 문서 빈도 기반 가중(IDF 계열)이 후보다.
3. **HR 문맥을 랭킹에 전달할 경로가 필요하다.** 분류 필터 파라미터나 질의 라우터의 분류 추론을
   검색에 넘기면 2번 유형이 해소된다.
4. holdout은 이제부터 **변경 전후 비교에만** 사용하고, 이 세트를 보고 alias를 추가하지 않는다.
   그렇게 하는 순간 holdout이 아니게 된다.
5. `NCS_SEARCH_EVAL_ENFORCE=true` 전환은 holdout 수치가 개선된 뒤에 검토한다. 현재
   holdout 기준 0.451은 0.7 게이트를 통과하지 못한다.

## 검증

- holdout 51건, 검색 오류 0건.
- 기대 능력단위 코드 54개 전부 서빙 DB에 존재함을 확인했다.
- 기존 40개 회귀 세트는 변경하지 않았다. `tests/fixtures/ncs_search_eval_nl.json` 미변경.
- `scripts/audit_ncs_search_precision.py`는 변경하지 않았다. `--input`으로 holdout 경로를
  넘기면 그대로 동작한다.
- DB와 온톨로지 데이터는 수정하지 않았다.

## 한계

- holdout 질의는 사람 실무자가 아니라 능력단위 정의문을 근거로 작성했다. 실제 HR 담당자의
  표현 분포와 다를 수 있으므로, 향후 실사용 로그나 담당자 인터뷰로 보강해야 한다.
- 경영기획 8건을 제외해 사무·기획 영역의 검색 품질은 이 수치에 반영되지 않았다.
