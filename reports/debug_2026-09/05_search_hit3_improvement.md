# 5단계 — 자연어 검색 Hit@3 개선

작성일: 2026-09-11

## 원인 분석

- 공식 NCS 명칭과 실무 표현이 다른 질의는 literal phrase/AND 후보가 없거나, 흔한 단어만 잡힌 OR 후보에 묻혔다.
- `연봉 협상`, `부가세`, `원천세`, `온보딩`, `사무용품`처럼 의미가 분명한 표현도 기존 토큰 확장이 phrase 또는 AND tier에서 결과를 찾으면 실행되지 않았다.
- 모든 짧은 단어를 일반 동의어로 확장하면 스포츠의 선수 연봉, 제조원가, 설비 외주처럼 다른 NCS 분야를 HR·총무로 오라우팅할 위험이 있다.

## 변경 계획

1. 공식 명칭과 차이가 큰 고특이도 복합 실무어만 별도 intent alias로 관리한다.
2. intent alias는 능력단위 검색에만 적용하고 기존 phrase/AND/OR tier와 점수는 변경하지 않는다.
3. 모든 SQL 값은 기존과 동일하게 파라미터 바인딩하고, 원천 DB와 온톨로지 상태는 수정하지 않는다.
4. 명시적인 타 분야 문맥은 alias를 차단하고, 의미가 모호한 제조원가·외주용역 매핑은 적용하지 않는다.
5. 40개 평가, 변형 문장, 타 분야 반례, 검색 벤치마크, 전체 테스트와 Vercel 미러를 검증한다.

## 구현 결과

### 검색 동작

- `src/ncs_mcp/search/core.py`와 Vercel 미러에 `intent_alias` tier를 추가했다.
- 실무어는 코드나 DB 행에 직접 고정하지 않고 검증된 공식 NCS 명칭 후보로만 확장한다. 주요 예시는 다음과 같다.
  - `연봉 협상 → 임금관리`
  - `퇴직금 정산 → 퇴직업무지원, 급여지급`
  - `온보딩 → 인력채용, 교육훈련운영`
  - `승진 심사 → 인력이동관리`
  - `직원 고충 → 노사갈등 해결`
  - `사무용품 → 비품관리`, `법인 차량 → 차량운영관리`
  - `사내 복지 → 복리후생지원`, `사옥 보안 → 총무보안관리`
  - `원천세 → 원천징수`, `부가세 → 부가가치세 신고`
- 매핑된 공식 용어는 능력단위명과 별칭에 가중치 3, 세분류·소분류에 2, 중분류·대분류·정의에 1을 적용해 정렬한다.
- 검색 응답에 실제 적용된 후보를 `query_intent_expansions`와 `matched_expansions`로 남겨 감사 가능성을 유지한다.
- `선수`, `스포츠`, `프로야구`, `프로축구`, `구단` 문맥이 있는 연봉협상은 HR alias를 차단한다.
- `제조 원가`, `외주 용역`은 전체 NCS에서 의미가 모호해 alias 대상에서 제외했다. 반례 테스트에서 자동차 제조원가와 설비보수 외주용역이 회계·총무로 강제 전환되지 않는 것을 확인했다.

## 검색 품질

평가 조건은 동일한 40개 질의, `scope=unit`, `limit=10`이다.

| 버전 | Hit@1 | Hit@3 | MRR@10 | 검색 오류 |
|---|---:|---:|---:|---:|
| 변경 전 | 0.4750 | 0.5000 | 0.5062 | 0 |
| 변경 후 | 0.8250 | 0.8750 | 0.8550 | 0 |
| 변화 | +0.3500 | +0.3750 | +0.3488 | 0 |

| 카테고리 | Hit@1 | Hit@3 | MRR@10 |
|---|---:|---:|---:|
| 인사 | 0.8750 | 0.8750 | 0.8750 |
| 노무 | 0.8750 | 1.0000 | 0.9375 |
| 교육 | 0.8750 | 0.8750 | 0.8750 |
| 총무 | 0.6250 | 0.7500 | 0.7125 |

- 기존 25개 질의는 순위를 유지했다.
- 15개 질의의 정답 순위가 개선됐다.
- 순위가 악화된 질의는 0개다.
- Hit@3 0.7 강제 게이트가 `pass`로 전환됐다.

미적중 5개는 `인력 수급 계획`, `교육 수요 조사`, `외주 용역 업체 선정`, `출장 증명서 발급 지원`, `제조 원가 계산`이다. 이 표현은 전체 NCS 범위에서 다른 직무와 충돌하므로 추가 문맥·분류 추론 없이 특정 HR 능력단위로 강제 매핑하지 않았다.

## 성능

intent alias가 적용되는 15개 질의를 같은 프로세스에서 기능 OFF/ON으로 각각 7회 교차 측정했다.

| 항목 | 변경 전 | 변경 후 | 변화 |
|---|---:|---:|---:|
| 질의별 실행값 전체 중앙값 | 127.175 ms | 89.387 ms | -29.7% |
| 가장 느려진 질의의 중앙값 변화 | - | - | -0.4% |

alias tier가 약한 fallback tier까지 내려가기 전에 공식 명칭 후보를 찾으므로 평가 대상에서는 지연도 감소했다. 이 수치는 로컬 warm DB 비교이며 Vercel 네트워크 지연을 포함하지 않는다.

## 위험 및 후속 과제

- 현재 40개 세트가 alias 설계에 사용됐으므로 완전히 독립적인 holdout이라고 볼 수 없다. 다음 단계에서는 신규 실무자 표현 50개 이상을 별도 holdout으로 만들고 기존 40개는 회귀 세트로 고정해야 한다.
- 남은 5개 질의는 질의 라우터의 HR 문맥 또는 분류 필터를 검색에 안전하게 전달한 뒤 개선하는 편이 단순 전역 동의어보다 안전하다.
